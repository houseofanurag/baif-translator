Project Purpose & Problem Statement

In deep rural field operations, training sessions, focus group discussions, and agricultural extensions often suffer from the Connectivity Block. Existing AI transcription and translation tools (e.g., cloud-based speech services, external SaaS APIs) completely fail in zero-signal zones.

The primary purpose of the BAIF Offline Translator is to provide a zero-connectivity, privacy-compliant, zero-operational-cost translation suite. It empowers field officers to capture, transcribe, translate, and hard-burn subtitles onto educational assets on-site using standard operator laptops without transmitting a single byte over the internet.

What We Have Built

Speech-to-Text Engine

Integrated faster-whisper (OpenAI Whisper) model processing raw audio and video containers into precise, timestamped dialogue transcriptions with VAD (Voice Activity Detection) filtering.

Neural Machine Translation

Bidirectional Translation: English ↔ Hindi/Marathi using NLLB-200 and Opus-MT models. Supports Hindi↔Marathi translation as well.

Native FFmpeg Subtitle Burner

Automated shell execution module utilizing ASS/SRT filters to hard-burn verified subtitle tracks directly into final output MP4 files with customizable font size and color.

Ad-Hoc Network Broadcast

Broad 0.0.0.0 host binding allowing nearby field devices (smartphones, tablets) to access the interface over a local pocket router or laptop hotspot.

Hardware-Adaptive Optimization Logic

The core system automatically adapts to host hardware resources:

🚀 GPU / Apple Silicon (MLX) Uses float16 floating-point precision for maximum throughput. Leverages unified RAM or VRAM buffers for faster inference.
💻 CPU Mode (Commodity Hardware) Forces dynamic int8 quantization, reducing memory footprint by up to 60% and enforcing thread containment to prevent OOM errors.

How to Use the Application

1. System Setup (Execute Once with Internet at Office)

Run the automated cross-platform bootstrapper script to compile virtual environments and pre-cache local model binaries:

# On Unix / macOS / Linux
chmod +x setup.sh && ./setup.sh

# On Windows
setup.bat

When prompted, select Production Mode (y) to download all models including Medium and Large. This ensures full offline capability.

2. Launching in Zero-Signal Field Areas

Start the backend offline server engine:

# On Unix / macOS / Linux
./run.sh

# On Windows
run.bat

3. Application Workflow

  1. Open http://localhost:8000 in your browser (or use host IP from mobile devices).
  2. Select Source Language from dropdown (Auto-Detect, English, Hindi, Marathi).
  3. Choose your target execution model size (Tiny, Base, Small, Medium, Large).
  4. Upload File: Drag & drop or select an audio/video file (MP3, WAV, MP4, MOV).
  5. OR Live Record: Click "Start Mic" to capture live audio directly.
  6. Click "Process & Transcribe" to run the Whisper AI engine.
  7. Review dialogue outputs in the Interactive Timeline Grid and make dialect corrections.
  8. Select Target Translation Language (English, Hindi, Marathi).
  9. Click "Run Translation Pipeline" to translate the transcript.
  10. Click "Build Subtitles" to generate SRT file.
  11. Click "Burn Hard Subtitles into Video" to trigger native FFmpeg subtitle burn-in.

Deployment Strategy

🏢 Central Hub Pre-Configuration: Technical managers run setup.sh / setup.bat once at regional head offices before distributing laptops to rural units.

📡 Field Hardware Portability: Laptops act as local server nodes. By enabling host Wi-Fi hotspot mode, up to 10 nearby field officers can log onto the host IP concurrently.

💾 Model Caching: All AI models (Whisper, NLLB, Opus-MT) are cached locally in ~/.cache/ during setup. No internet required after initial setup.

🔄 Zero Downtime Updates: New model versions can be pre-downloaded at regional offices and distributed via USB drives if needed.
